# 业务规则

设计和开发落地页时必须优先遵守以下业务逻辑。先满足业务规则，再进行视觉和文案优化。

## 硬性规则

1. 手机号和邮箱这两种联系方式至少启用一个。
2. 选择 `中文` 课程时，年龄和中文水平必须收集，因为会影响课程定级。
3. 选择 `英文` 或 `数学` 课程时，年级必须收集，因为会影响课程定级。
4. 地区字段必须存在且启用，不可删除。
5. 所有开启的留资字段都视为用户必填字段。
6. 表单必须包含清晰可见的隐私同意模块。
7. 页面只能渲染配置文件内出现的字段、科目和流程，禁止新增未配置科目或无依据的预约选项。

## 约课开关与多娃多科组合逻辑

| 约课开关 | 多娃 / 多科配置 | 最终体验 |
| --- | --- | --- |
| 关闭 | 多娃关闭，多科关闭 | 单个孩子留资，不出现课时选择。 |
| 关闭 | 仅开启多娃 | 首娃提交后，在结果页继续为其他孩子报名。 |
| 关闭 | 仅开启多科 | 孩子提交后，在结果页继续报名其他已配置课程。 |
| 关闭 | 多娃和多科都开启 | 首娃提交后，在结果页继续为其他孩子报名，并选择已配置课程。 |
| 开启 | 多娃关闭，多科关闭 | 单个孩子填写信息并选择试听课时间。 |
| 开启 | 仅开启多娃 | 首娃约课后，继续为其他孩子填写信息并选择课时。 |
| 开启 | 仅开启多科 | 孩子约课后，继续预约其他已配置课程。 |
| 开启 | 多娃和多科都开启 | 首娃约课后，继续为其他孩子选择已配置课程并完成约课。 |

## 实现要求

- 当约课关闭时，不展示日期、时间、老师排班或课时选择控件。
- 当约课开启时，必须展示清晰的日期选择、时间选择、预约摘要和成功/失败状态。
- 当多娃开启时，流程最多支持到 `maxChildren`，不能超过配置上限。
- 当多科开启但配置中只有一个科目时，只展示该科目，不暗示有其他课程可选。
- 当缺少真实数据、评价、资质或合作背书时，使用可编辑占位内容，不编造真实声明。
